# Unweb

Unweb is a tiny browser where every visit is a first visit. Every window is a stranger: it starts with no history, no logins and no cookies, and when it closes everything it collected is deleted. Several strangers can run side by side, each kept apart from the others and from the normal browser. It runs on the system web engines (WebView2, WKWebView, WebKitGTK) through Tauri 2.

Domain: unweb.org

## Screening record

Agreed with YK on October 23, 2026.

Money: free open-source app. Paid features later for professionals: saved session setups ("5 strangers in 5 countries"), side-by-side screenshot comparison and team sharing. SEO and ad-verification people already pay for tools that show clean, unpersonalized results. No revenue model is approved.

Real problem: your normal browser is soaked in your history and logins, so you never see what a stranger sees. Incognito windows share one session with each other and are awkward to run in parallel.

Plain-language technology: "A browser where every visit is your first visit. Open as many strangers as you like, side by side. Close them, and they never existed."

Differentiation: multi-profile browsers exist, but they're mostly heavy Chromium-based tools aimed at managing many accounts. Unweb is tiny, open source and built around the opposite idea: no accounts, no memory, a clean look every time.

What a stranger still gives away, to be said plainly on the site: the IP address and rough location; the device (all strangers on one machine share screen size, fonts and hardware, so fingerprinting could link them); and it is not a malware sandbox (same system engine).

## Design

Windows and strangers (crates/unweb/src/strangers.rs, window.rs; Tauri "unstable" multi-webview): a window "win-<hex>" holds the bar "bar-<hex>" (ui/bar.html, 44 px, with a small store of the window's own) and one to four strangers. A stranger "stranger-<hex>" is a tile of two webviews: its strip "strip-<hex>" (ui/strip.html, 28 px: language, cookie count, close) above its page "page-<hex>", both with the stranger's throwaway store. Grid: one, two or three in a row, four as two by two (window::grid, tile_rects). A new window with one stranger is what New stranger and the command line open. On Windows and Linux the store is a data folder `<app data>/strangers/run-<random>/<label>` passed as data_directory, which gives each stranger its own WebView2 environment or WebKitGTK WebContext, and so its own cookies, storage, HTTP cache, service workers and everything else. On macOS it is incognito (a new non-persistent WKWebsiteDataStore per webview), which keeps nothing on disk.

Closing: a window's CloseRequested is prevented and the close goes through Strangers::retire_window, which clears each stranger's engine data (Linux WebsiteDataManager::clear ALL; macOS about:blank plus removeDataOfTypes) and destroys the window; on Destroyed, window_closed wipes every stranger's folder and the window's own. Closing one stranger of several (its strip's ×, or a language change) is retire_tile: clear, close its two webviews, lay the window out again, wipe its folder. Strangers::closed wipes a folder: it waits until nothing in the folder has changed for 4 s (at most 20 s), deletes it (retrying while files are held, up to 30 s), then watches it for 10 s and deletes it again if anything writes it back. This is needed because Tauri 2.12 keeps a WebKitGTK WebContext alive for the app's lifetime (tauri issue 14626), and its network process writes cache records (SubResources, dump.json) 2 to 7 s after a page closes, recreating the folder. When the last stranger closes, the app waits (up to 90 s) for running wipes before exiting. Each running copy has its own run folder and holds a lock on `run-<random>.lock` beside it (std File::try_lock; the file is created and locked as run-<random>.lock.new and then renamed, so a copy starting at the same moment never sees it unlocked, and purges skip lock files under 10 s old). At start, run folders whose lock is free (a crash, a kill, a page's window.close) and anything that isn't a run folder are deleted; a live copy's run is left alone. At exit the run folder is removed, then the lock.

Outside the folder: Linux sets MESA_SHADER_CACHE_DISABLE, MESA_GLSL_CACHE_DISABLE and __GL_SHADER_DISK_CACHE=0 at the top of main (engine processes inherit them) and turns off WebKitGTK's persistent credential storage per stranger (webkit2gtk v2_30). Windows passes --disable-gpu-shader-disk-cache along with wry's default --disable-features list (additional_browser_args replaces it). Driver shader caches on Windows and macOS are a stated gap.

Bar, strips and commands (build.rs AppManifest): go, back, forward, reload, new_stranger, side_by_side, save_setup, open_setup, delete_setup and compare are granted only to "bar-*" (capabilities/bar.json) and act on the calling bar's own window (window::window_of_bar); set_language, set_location and close_stranger only to "strip-*" (capabilities/strip.json), for the calling strip's own stranger; save_compare only to "cmpview-*" (capabilities/compare.json). The strip's on_navigation allows only /strip.html on the app's exact origin. Back and forward use each engine's native call (nav.rs), so page code can't trap them. The page's on_navigation allows http, https, about, blob and data, plus the app's start page only (no query or fragment; never bar.html or ipc.localhost); new-window requests are denied and opened in the same page; downloads are refused. The bar's on_navigation allows only its own /bar.html on the app's exact origin (tauri://localhost on Linux and macOS, http://tauri.localhost without a port on Windows), so a dropped link can't replace it (review round 1 found it could, round 2 found tauri.localhost on another port could). Every label ends in 16 random hex digits (win-, bar-, stranger-, strip-, page-), since pages can read their window's and their own label through Tauri's metadata. The bar shows the first stranger's address and whether any stranger can go back or forward (eval of window.unwebShow on page load, title change and the bar's own load). Linux layout: linux_layout.rs packs the bar (fixed height) and a GTK grid of per-stranger boxes; a new stranger's two widgets are the unplaced ones Tauri appended to the window box, remembered per stranger on the main thread. Windows and macOS set bounds on resize (window::layout).

Cookie counter (counter.rs, crates/unweb-core): every two seconds and on every page load, each stranger's page store is read with Webview::cookies (off the main thread; names, domains and HttpOnly only) and counted with unweb_core::count_cookies against the site the page shows; describe() gives the strip's line. On macOS the store is read with WKHTTPCookieStore getAllCookies directly (counter::read_cookies), because wry's cookies() spins the main run loop from inside the main thread, which stalled window creation (self-test hangs, the 0.2 Intel release hang). unweb-core is the trimmed one-time copy of Watchkeeper's core (commit ec99755: site_of_host, site_of_url, StoredCookie), credited in NOTICE.

Language per stranger: Windows only (LANGUAGE_PER_STRANGER), as --lang and --accept-lang switches of the stranger's own WebView2 environment, so it applies from the first request; changing it is Strangers::change_language, a new stranger in the old one's place at the same address. WebKitGTK's set_preferred_languages turned out to be process-wide (one stranger's German reached the others in the self-test), and WKWebView has one language per app, so on Linux and macOS the menu is off with the reason (NO_LANGUAGE_REASON). macOS uses TitleBarStyle::Transparent, since Tauri's default style runs the content under the title bar. On macOS, retire navigates the page to about:blank and clears its store before destroying the window, because WKWebView otherwise keeps a closed stranger's service worker running for seconds.

Locations (location.rs): a stranger's Settings are its language and an optional proxy, both fixed for its life, so changing either is Strangers::change_settings (a new stranger at the typed address). parse_location takes http:// and socks5:// (host:port alone means http), parses the host as http so it is lowercased and IDNA-checked, allows only DNS names and IPv4, needs a port, and refuses credentials, paths and IPv6 (wry writes IPv6 hosts without brackets). WebView2: wry adds its proxy switch only when the app gives no switches, so store() adds --proxy-server, --proxy-bypass-list=<-loopback> (Chromium otherwise sends loopback direct) and --force-webrtc-ip-handling-policy=disable_non_proxied_udp. WebKitGTK and WKWebView: WebviewBuilder::proxy_url (per web context, per data store; Tauri's macos-proxy feature; macOS 14 needed, checked by location::supported). With a location the page gets NO_WEBRTC in every frame and, on Linux, enable-webrtc off. A proxy that is down loads nothing (self-test). Known gap on macOS, released as stated at YK's choice (October 24, 2026): a stranger whose proxy is down goes direct. Tried and removed: nw_proxy_config_set_failover_allowed(false) on the page's store, and a relay per stranger on 127.0.0.1 answering 502; macOS went direct with both. The self-test reports it there without judging (DOWN_PROXY_GOES_DIRECT). The Network framework calls behind wry's macos-proxy need macOS 14, so minimumSystemVersion is 14.0. Known: deleting the last setup unlinks setups.json.lock, so three copies changing setups at that moment could lose one save. macOS's network layer sends loopback addresses past the proxy (stated in the README); the self-test uses this machine's network address there (Server.lan) and doesn't judge loopback on macOS. wry's url() panics on macOS when WKWebView has no URL yet, so pages' addresses are read through window::page_url.

Setups (setups.rs): setups.json in app_config_dir (the self-test's own folder in a self-test), format "unweb-setups" version 1, name plus per stranger language and location only; names trimmed, 1 to 60 characters, no control characters; at most 50 setups, 4 strangers each; written to setups.json.tmp then renamed; each change rereads the file; an unreadable file is renamed setups.json.bad-<secs>; entries that don't pass the checks are cleaned on reading; deleting the last setup deletes the file and an empty folder. save_setup, open_setup and delete_setup are granted to bar-* only; the bar gets the names with unwebShow.

Compare (capture.rs, compare.rs): compare (bar-*) takes each page's screenshot (WebKitGTK snapshot to PNG through cairo, WebView2 CapturePreview into a memory stream, WKWebView takeSnapshot then TIFF to PNG), and opens a window "cmp-<hex>" whose page "cmpview-<hex>" (ui/compare.html, its own store, wiped on Destroyed) gets the screenshots and captions (language, location, cookie line, scheme+host+path only) by eval once compare.html has loaded. The page draws the strip on a canvas; Save image sends it to save_compare (cmpview-* only), which checks it is a PNG under 64 MiB and writes unweb-compare-<UTC>.png to Downloads with create_new (-2, -3 when taken). The app pages' CSP allows data: images for this.

Self-test watchdog: STEP names the part running; after 280 s the self-test prints where it was and exits 3 (the scripts give up at 300 s).

Self-test servers: site (127.0.0.1, logging each request's source port), third party (localhost), and HSTS (hsts.rs: rustls with ring, an HTTPS server sending HSTS and a plain server on another port that records whether it got HTTP or a TLS handshake). testproxy.rs: an HTTP proxy and a SOCKS5 proxy that log each onward connection's local port and resolve *.unweb.test to 127.0.0.1, and a UDP listener standing in for a STUN server. HSTS needs scripts/test-ca.sh (throwaway CA trusted system-wide plus a hosts entry; CI runners only) and UNWEB_TEST_TLS; without it the check is "not run" and fails when CI is set. Adding the CA to the cloud workspace was refused by the permission check, so HSTS is verified in CI only.

## Code and completion standard

Tests for every operation, plus failure tests aimed at the main promise: nothing carries over between strangers, from a closed stranger to a new one, or into the normal browser, and nothing is left on disk after closing. The end-to-end self-test (unweb --selftest, src/selftest.rs) runs the real app on the OS's own engine against a local site (127.0.0.1) and a third party (localhost); the servers' request logs (Cookie headers, revalidation headers) and the pages' own reports are the ground truth. Every check that something is absent has a control that shows the same thing present in the stranger that left it. Record results with scripts/record-results.sh, which replaces test/results/latest/<os>; git history keeps earlier runs. Every number on the site comes from recorded results with its conditions.

CI runs on every push to main on Linux, macOS and Windows: rustfmt, clippy with warnings denied, all tests, and the self-test (under Xvfb on Linux), uploading the results and posting the self-test lines as annotations. Toolchain pinned to Rust 1.97.0. Before calling a release complete, get an independent review from a separate agent that has not seen the implementation, fix findings, rerun checks and record again.

Releases go out through an automated workflow after CI succeeds on the exact commit, building installers for Windows (.msi), macOS (.dmg) and Linux (AppImage and .deb). Early versions ship unsigned, with install instructions on the site; signing certificates are YK's later decision. Never ask YK to publish a release. Version 0.0.x is never released.
